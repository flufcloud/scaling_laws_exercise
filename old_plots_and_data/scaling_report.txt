I coded a custom Pallas kernel that fuses the up and down projection for a Mixture-of-Experts style linear layer. The kernel tiles over the final B x D matrix with tiles of B_tile and D_tile, along with F_tiles for accumulation. The kernel imitates ragged_dot's strategy for computing ragged matmuls; in particular, it uses the fact that the maximum number of logical B_blocks required is equal to the number of expert boundaries + the number of physical B_blocks needed to tile over the full B dimension. 

The kernel iterates over a D_blocks x B_blocks x F_blocks grid ie a j x i x k grid where for each iteration, we load the ith B_block x D row from the input, the kth D x F_block column from W_up, and the jth F_block x D_block tile from W_down. The iteration order is designed to exploit how Pallas TPU kernels interact with memory references. For each (j, i), the output reference is fixed for all k, allowing us to safely accumulate into it. However, since we are computing a ragged operation, we have to make j the slowest changing dimension because we may revisit physical blocks with different logical blocks. 

For example, suppose half of the first physical block is routed to Expert 1 and half to Expert 2. Then, for i = 0 and j = 0, we accumulate Expert 1's computation into the output block. If we make i the slowest changing dimension, then assuming our output reference is given (physical(i), j) we write to the (0, 0) output reference, and then the (0, 1) physical reference, and so on. But physical(0) = physical(1), so for i = 1 and j = 0, we revisit the (0, 0) output reference. This overwrites the results of Expert 1's computation (since we cannot read from output buffers in general).

Takeaways:
- Decreasing the number of times the fused kernel tiles over D drastically improves the fused vs. unfused ratio. I hypothesize this is because for each tile of D j, we iterate over all k to accumulate into the output tile and consequently load the entire W_up matrix.
- Increasing B improves the fused vs. unfused ratio. This makes sense because the fused kernel avoids materializing the intermediate B x F projection.
- Changing the tile sizes of B and F have minimal influence on the fused vs. unfused ratio. I hypothesize this is because the number of tiles for F do not alter the memory traffic, and that for large enough B_tile we are compute bound, so increasing B_tile beyond it does not substantially improve performance. I note however that if B_block is small enough such that it contains rows routed to many different experts, the fused kernel's performance degrades.
- Increasing the number of experts improves the fused vs. unfused ratio. I found this surprising: when I profiled the code, I discovered that the time taken for an individual up/down projection exceeded the total time taken for the full fused operation. This indicates that ragged_dot incurs overhead per-expert that the fused kernel is avoiding.
